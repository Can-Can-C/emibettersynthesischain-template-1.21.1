## 新功能：AE2 终端内自动合成网络材料（需求 11，2026-08-15）✅ 用户验收通过

### 问题（用户反馈"无法识别 AE 物品 / 树只能检测一层 / 无法合成"）
AE2 合成终端里网络材料在**识别**与**放料**两个环节都不可见：
1. **识别层**：AE2 的 `AbstractRecipeHandler.getInventory` 只在配置 `exposeNetworkInventoryToEmi=true`（**默认 false**，反汇编 iconst_0 实证）时并入网络条目 → 默认关闭时库存只有玩家背包 → 树标红/`canAfford` 看不到网络（"无法识别 AE 物品"）。
2. **放料层**：EMI `getStacks/clientFill` 用 handler.getInventory（同前不含网络）判断可合成 + 只能从 inputSources 槽（背包+快捷栏+合成格，无网络）拾取 → 背包无料时 `getStacks` 返回 null，放料失败（日志实证 `getStacks null for oak_planks`）。
3. **树只检测一层**：`hasCraftingMenuOpen` 只认原版 CraftingMenu → AE2 合成终端（3×3 合成格）不被认可 → 中间 3×3 材料误标红。

### 调试过程（诊断日志逐层定位）
- `EBS auto-craft / chain start`：start 静默失败 → 加日志 → 定位到 placeStep 内 done。
- `EBS chain placeStep: fillViaEmi failed`：预检全过（pickNext/工作台/fit/afford）→ 卡在放料。
- `EBS fillViaEmi: getStacks null (handler=EmiUseCraftingRecipeHandler)`：**确认 getStacks 用 AE2 原版 getInventory（配置 false → 无网络）** → clientFill 方案在 AE2 终端不可行。

### 最终方案（javap 实证 AE2 19.2.17）
- **识别**：`Ae2Support.mergedInventory(screen)` 自建"槽位（inputSources）+ 网络（getClientRepo 条目，`EmiStackHelper.toEmiStack(GenericStack)` 转换，组件保真）"合并库存，**不依赖 AE2 配置**；`CraftInventory.currentScreenInventory/current` 在 AE2 合成终端优先返回 → 树标红/预检全链路可见网络。
- **放料**：`ClientCraftChain.fillViaEmi` AE2 分支改走 **`handler.craft(recipe, ctx)` = AE2 transferRecipe**（`findMissingIngredients` 查合成格/背包/网络缺料，服务端从背包+网络提取材料放进合成格，网络借料机制）——**替代 clientFill + REFILL**（REFILL 提取方案因 getStacks 检查无法绕过而废弃，整体删除）。
- **默认配方唯一**（用户指定"设默认，不要逐个尝试，断了就断了"）：树标红 `producersOf` 与链条 `findProducerToCraft` 都**只用 BoM.getRecipe（默认配方）**，删除 getRecipesByOutput 全部候选/缓存；默认链断 → 标红/停止。
- **3×3 认可**：`hasCraftingMenuOpen` 增加 AE2 合成终端判定。
- 普通界面（工作台/背包/精妙背包）放料仍用 EMI clientFill，行为不变。

### 验证
- `./gradlew build` → **BUILD SUCCESSFUL**（多轮：首轮编译错误修复；诊断日志加/删；REFILL 删除；AE2 放料切换）。
- **用户 runClient 验收通过**：AE2 终端、背包无料仅网络有料 → V 自动合成成功（材料直接网络进合成格→合成→取产物）；树按默认配方识别（默认链断即红）；中间层按默认配方链合成；Shift+V 连续；AE2 未装环境不受影响。**（✅ 2026-08-15）**
- 诊断日志清理：临时 INFO 诊断降为 debug（`EBS chain start/placeStep/fillViaEmi/auto-craft` 前缀）。
