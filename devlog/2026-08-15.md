## 完成

### 合成树 UI（承接 v2.1.0）
- **数字大小可调**：`Config.TREE_NUMBER_SCALE`（默认 0.5，范围 0.25-1.0）；EMI 设置页"数字大小(%)"（25-100 整数映射）；`TreeRenderer` 数量/拥有量/流体用量统一用 `numberScale()`。
- **数量显示修复**：数量文字从 `p.y()+12` 改为 `p.y()+ICON-2`（图标格右下角内侧），不再压在物品下方/外溢。
- **数量缩写扩到 k/M/G/T**：`formatItemAmount` 1000 进制多级（一位小数去尾零），与流体 `mB/L/K L/M L/G L` 一致。
- **总材料行（leafTotal）超宽换行铺满 + 所有材料行统一 wrap**：原来超宽项被丢弃且向右溢出遮挡右侧最终产物；改为按材料区右界（`matRight`=分割线 `dividerX`，材料不越过分割线）**换行铺满**；新增 `placeRowItems`/`rowItemLines`，`contentHeight` 同步计物理行数。中间行（rows/directInputs）也统一换行。
- **左上角拥有量**：非目标物品节点，`CraftInventory.count(content) < 需要量` 时左上角红字显示当前拥有量（`formatItemAmount`），足够不显示。

### 数量感知（自动合成）
- **同种物品需多个只合一次**：`pickNext`/`placeStep` 原用 EMI `canCraft`（按"种类"判断，1 个木板也算够）→ 改用数量感知 `goalReady()`/`canAfford()` + `totalNeedOf`（**同种材料多槽聚合总量**，如 6 木板槽 → need 6）。
- **背包有 1 个木板不再向下拆解**：`InternalHelperImpl.findRecipe` 叶子判断原用 `content.getAmount()`（单次量）→ 改用累计总需要量（`findRecipe(content, needAmount, forbidden)`）；`addNeed` 累加后若"叶子但总 need 超库存"则**解叶子化**重新拆解（Agg.recipe 非 final，batch 归零重展开）。
- **tag 子材料递归修复**：`findProducerToCraft` 对 `TagEmiIngredient` 子材料原直接递归（`BoM.getRecipe(tag)` 恒 null）→ 改为遍历 tag 具体成员递归找可合成的（如缺 `#planks` → 遍历 oak_planks → 原木→木板）。

### 放料与取产物（模组界面）
- **放料复用 EMI clientFill**：`EmiRecipeFiller.clientFill(handler, recipe, screen, stacks, Destination.NONE)` 一次性放料（光标受控、形状感知），替代手写逐格右键放料（光标有物时取一半→32 个到指针/一格多木板）。
- **`Destination.NONE`**（只放料不移走）——`INVENTORY` 会把材料移回背包导致结果槽空、`CURSOR` 留光标卡鼠标。
- **取产物（`takeOutput` 分阶段 + 背包数量验证）**：
  - `clickSlot`：用 `menu.slots.indexOf`/`container+containerSlot` 匹配菜单 index（模组 handler 返回的 `Slot.index` 是容器 index，如精妙背包 172 > slotsSize 156 → 越界）。
  - 分阶段：`retries==0` QUICK_MOVE（shift，服务端自动堆叠）→ `retries==1` PICKUP+放回空槽 → `retries>=2` handler.craft fallback。
  - `onShowEnd` 用**背包产物数量增加**验证取走成功（模组 `output.hasItem()` 可能恒 true 不刷新，不能依赖）；未增才进下一阶段/重试。
- **精妙背包合成插件**：能取走产物、连续合成继续（QUICK_MOVE 生效应堆叠；否则 PICKUP 放空槽不堆叠——待进一步验证）。
- **AE2 合成终端**：`CraftingTermSlot`（index 50 正确）QUICK_MOVE/PICKUP/handler.craft 都无法取走——AE2 取产物走其**菜单 action 机制**（`AEBaseMenu.clicked`+`registerClientAction`），**需 AE2 联动模块**（待办）。

### AE2 合成终端取产物（原待办 → 已完成，2026-08-09）
- 根因（javap 实证 AE2 19.2.17）：`CraftingTermSlot.mayPickup()` 恒 false → vanilla QUICK_MOVE/PICKUP 与 `AEBaseMenu.quickMoveStack` 均拒绝；EMI handler.craft = transferRecipe 只放料。唯一途径 = AE2 action 机制：`InventoryActionPacket` → `AEBaseMenu.doAction` → `CraftingTermSlot.doClick`（客户端普通左键 = CRAFT_ITEM）。
- 实现：`build.gradle` 加 `compileOnly libs/appliedenergistics2-19.2.17.jar`；新增 `client/Ae2Support.java`（`ModList.isLoaded("ae2")` 门禁 + 方法体惰性引用，未装 AE2 短路）；`ClientCraftChain.takeOutput` AE2 分支发 CRAFT_ITEM。
- 细节（后续 bug 修复）：
  - **合成后重新填充**：doClick 的 postCraft 从网络提取等价材料补回合成格 → 取产物后逐格 vanilla QUICK_MOVE 清格（材料回背包 + 触发 `slotsChanged`）。
  - **结果槽残留**：`clearToPlayerInventory()` 用 `setItemDirect` 绕过槽不触发 `slotsChanged` → 结果槽服务端残留 → 弃用，改 QUICK_MOVE 清格（`CraftingMatrixSlot.remove` → `slotsChanged` → 结果槽清空）。
  - **误重试多合成**：AE2 每步发 CRAFT_ITEM + 最多 9 个清格包 → `resultRetryTicks()` AE2 菜单 12 tick。
- 详情见 `devlog/2026-08-09.md` 与 `update.md`。
