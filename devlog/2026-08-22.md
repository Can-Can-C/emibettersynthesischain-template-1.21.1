## 修复（发布后回测：AE / 背包中存储物读取不准）
- **现象**：在 AE 终端与背包（容器）里，树显示的存储量/可合成判定"有时不准"。
- **根因 1（代码实证）**：`maybeRefreshOnInventoryChange` 只哈希**玩家背包 36 格 + 菜单类名**——AE 网络内容变化（玩家背包没动）、背包容器内挪动物品**检测不到** → 树缓存不重建，标红/可合成判定/叶子展开停留在旧快照。**修复**：每 5 tick 追加①当前容器菜单**全部槽位**内容哈希（背包本体/合成格/甲胄副手也顺带覆盖）；②`Ae2Support.networkSignature()`（ME 终端打开时对 `repo.getAllEntries()` 条目 `getWhat().hashCode()` 组合哈希，非 ME 终端返回 0）。
- **根因 2**：`mergedInventory` 原仅限合成终端（`CraftingTermMenu`）——**普通 ME 存储终端**看树时网络完全不可见（AE2 的 exposeNetworkInventoryToEmi 默认 false → handler 库存只有玩家背包）。**修复**：门禁放宽为 `MEStorageMenu`（javap 实证 `CraftingTermMenu extends MEStorageMenu`，覆盖普通存储终端/合成终端/无线）。
- 构建：`./gradlew build` → BUILD SUCCESSFUL。
- **剩余已知误差（非本 mod 可完全消除）**：AE2 客户端 repo 同步滞后数 tick（AE2 自身机制）；同种物品不同 NBT 组件不跨条目合并计数（Q6 已知限制，会话 1 记录）。

# 多版本 Phase 11.2c：26.1.2-neoforge 核心移植（2026-08-22 会话 3 续）

## 完成：26.1.2-neoforge 全量源码编译通过（BUILD SUCCESSFUL）
- 复用 1.20.1 的经验与差异清单，但 **26.1.2 是 MC 大改造版本**，实测差异：

### 26.1.2 MC API 差异（javap 实证，供后续版本复用）
| 旧（1.21.1/1.20.1） | 26.1.2 |
|---|---|
| `net.minecraft.resources.ResourceLocation` | **`Identifier`**（同名包；`tryParse/parse` 工厂） |
| `GuiGraphics` / `Screen.render(GuiGraphics,…)` | **`GuiGraphicsExtractor`** / **`extractRenderState(GuiGraphicsExtractor,int,int,float)`**（渲染管线改"提取渲染状态"） |
| `g.drawString(font,…)` | `g.text(font,…)` |
| `g.renderTooltip(font,lines,Optional,x,y)` | `g.setTooltipForNextFrame(List<FormattedCharSequence>,x,y)`（`Component.getVisualOrderText()`） |
| `g.pose()`（PoseStack，3D，`pushPose/translate(x,y,z)/scale`） | **`org.joml.Matrix3x2fStack`**（2D：`pushMatrix/popMatrix/translate(x,y)/scale(x,y)`；**无 z 轴** → 数字 z=200 深度技巧废弃） |
| `ClickType` / `handleInventoryMouseClick(…,ClickType,…)` | **`ContainerInput`**（常量同名 PICKUP/QUICK_MOVE…）/ **`handleContainerInput(int,int,int,ContainerInput,Player)`** |
| `KeyMapping(name,key,categoryStr)` | `KeyMapping(String,int,Category)`；`Category(Identifier)` |
| `Screen.hasControlDown/hasShiftDown` | 移除 → GLFW 直读 `Window.handle()` |
| `RecipeBookMenu.getGridWidth/Height` | 移除 → 按 `CraftingMenu`(3×3)/`InventoryMenu`(2×2) 判定 |
| `ShapelessRecipe.getIngredients()` | 移除（ingredients 私有）→ 按 2×2；网格实际放下由 canFitCurrentGrid 兜底 |
| `TagParser.parseTag` | `parseCompoundFully`（throws CommandSyntaxException） |
| `BuiltInRegistries.ITEM.get(id)` 返回 Item | 返回 `Optional<Reference<Item>>`；`new ItemStack(Holder)` 可接 |
| `ItemStack.parse(access,tag)` / `save(access)` | 移除 → **CODEC**：`ItemStack.CODEC.parse(RegistryOps.create(NbtOps.INSTANCE,access), tag)` / `encodeStart(...)` |
| `Inventory.items` | **private** → `getContainerSize()/getItem(i)` |
| `net.minecraft.client.Window` | 移到 `com.mojang.blaze3d.platform.Window`（`handle()` 取原生句柄） |

### 保留不变的（好消息）
- `RecipeHolder`（EMI `getBackingRecipe()` 仍返回 RecipeHolder）、`isSameItemSameComponents`/`hashItemAndComponents`、`EmiDrawContext.wrap(GuiGraphicsExtractor)`、BoM/EmiScreenManager/widgets 与 1.1.24 同构。
- 26.1.2 的渲染 mixin 注入点：BoMScreen/AbstractContainerScreen 目标方法改 `extractRenderState`；SidebarPanel.render(EmiDrawContext,…) 不变。
